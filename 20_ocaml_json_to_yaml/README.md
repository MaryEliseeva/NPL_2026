# 20. OCaml — конвертация JSON в YAML

## Постановка задачи

Преобразовать JSON-документ в **YAML** — формат конфигураций, где вложенность задаётся отступами, а не скобками. Результат должен читаться любым YAML-парсером обратно в **те же самые данные** (те же типы и значения), поэтому самое тонкое место — решить, какие строки можно писать без кавычек.

Решение состоит из двух частей, библиотеки не используются:

1. **Парсер JSON** — рекурсивный спуск по тексту; строит дерево типа `json`. Тип описан как **алгебраический тип данных** (variant) — значение ровно одного из видов: `Null | Bool | Num | Str | Arr | Obj`, и компилятор проверяет, что код обрабатывает каждый вид. Поддерживаются все escape-последовательности JSON, включая `\uXXXX` и **суррогатные пары** (так в JSON кодируются символы вне основной плоскости Unicode, например эмодзи) — они перекодируются в UTF-8. Порядок ключей сохраняется. Ошибка сообщается с номером строки и позиции.
2. **Генератор YAML** — обходит дерево:
   - объект → `ключ: значение`, вложенный объект/массив — с отступом в 2 пробела;
   - массив → строки `- элемент`; объект внутри массива начинается на строке с дефисом;
   - пустые объект и массив → `{}` и `[]`;
   - многострочная строка → **блок** `|` (текст как есть, с отступом); индикатор `|-`/`|`/`|+` сохраняет количество завершающих переводов строк;
   - строка пишется **без кавычек**, только если YAML не прочтёт её как что-то другое. В кавычки берутся строки, похожие на число (`"123"`, `"1.10"`), логическое значение или null (`"yes"`, `"null"` — в YAML 1.1 `yes`/`no`/`on`/`off` тоже логические), начинающиеся со служебного символа (`-`, `#`, `[`, `&`, `*`, …), содержащие `: ` или ` #`, пустые, с пробелами по краям, с управляющими символами;
   - числа с экспонентой нормализуются (`1.5e10` → `1.5e+10`), чтобы их одинаково понимали парсеры YAML 1.1 и 1.2.

## Входные данные

- `config.json` — пример со вложенными объектами и массивами, кириллицей, `\u`-последовательностями и эмодзи, многострочной строкой и набором «каверзных» строк (`"yes"`, `"123"`, `"a: b"`, `"#tag"`, пустая строка и т.д.);
- `broken.json` — некорректный JSON для демонстрации сообщения об ошибке.

## Запуск
### Через Docker

Команда скомпилирует программу внутри контейнера и сохранит `config.yaml` в текущей папке:

```bash
docker run --rm -it -v "$PWD":/app -w /app ocaml/opam:debian-12 sh -lc \
  'ocamlopt json2yaml.ml -o json2yaml && ./json2yaml config.json config.yaml'
```


Нужен OCaml 4.14+ (`sudo apt install ocaml` или opam).

```bash
ocaml json2yaml.ml config.json                 # YAML в консоль (интерпретатор, без компиляции)
ocaml json2yaml.ml config.json config.yaml     # YAML в файл
ocaml json2yaml.ml broken.json                 # пример ошибки

# или скомпилировать в машинный код:
ocamlopt json2yaml.ml -o json2yaml && ./json2yaml config.json
```

Корректность проверялась обратным чтением: `yaml.safe_load(вывод) == json.load(config.json)` (Python) — данные совпадают.
