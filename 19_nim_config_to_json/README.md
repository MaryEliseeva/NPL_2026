# 19. Nim — конвертация конфигурационного текстового формата в JSON

## Постановка задачи

Преобразовать конфигурационный файл в **блочном формате** (описан ниже) в **JSON** — с сохранением вложенности, типов значений (числа, логические значения, `null`, строки, списки) и порядка параметров. При синтаксической ошибке программа должна сообщать её место (строку и позицию) и понятную причину.

Разбор выполняется **рекурсивным спуском**: для каждой конструкции формата написана своя процедура (тело блока, значение, список, строка в кавычках), а вложенный блок разбирается рекурсивным вызовом той же процедуры, что и весь файл. Результат строится в дереве `JsonNode` стандартного модуля `std/json` и печатается с отступами.

## Синтаксис исходного формата

```
# комментарий до конца строки (также //)
ключ = значение                     параметр
блок {                              блок (секция) — может содержать
    ключ = значение                 параметры и другие блоки
    вложенный { ... }               любой глубины
}
ключ = { a = 1; b = 2 }             блок можно записать и как значение, в одну строку
```

- **Ключ** — буквы (в т.ч. кириллица), цифры, `_`, `-`, `.`.
- **Разделители параметров** — перевод строки или `;`.
- **Значения:**

| Запись | Тип в JSON |
|---|---|
| `42`, `-7` | целое число |
| `1.4`, `15.5` | дробное число |
| `true`, `false` | логическое |
| `null` | `null` |
| `"текст"` | строка; внутри допустимы `\"`, `\\`, `\n`, `\t` |
| `текст без кавычек` | строка до конца строки (пробелы по краям обрезаются) |
| `[a, "b, c", 3]` | список; может занимать несколько строк; элемент с запятой — в кавычках |

- **Повтор блока** с тем же именем превращается в массив объектов (`user { ... }` дважды → `"user": [{...}, {...}]`). Повтор обычного параметра — ошибка.
- Значения, содержащие `#` или `//`, нужно брать в кавычки (иначе это начало комментария).

### Чем формат отличается от INI

| | INI | Блочный формат |
|---|---|---|
| Структура | плоская: `[секция]` + `ключ=значение`, секции не вкладываются | блоки `имя { ... }` вкладываются на любую глубину |
| Границы секции | секция длится до следующего `[заголовка]` | блок явно ограничен `{` и `}` |
| Типы значений | всё — строки, тип угадывает программа | числа, `true`/`false`, `null`, строки в кавычках |
| Списки | нет (только `key1=`, `key2=` или своя договорённость) | `[a, b, c]`, в том числе многострочные |
| Повтор секции | не определено / ошибка | массив объектов |
| Несколько параметров в строке | нет | через `;` |
| Комментарии | `;` или `#` | `#` или `//` (`;` — разделитель параметров) |

Пример того же по смыслу в INI потребовал бы искусственных секций `[server.timeouts]`, `[user.1]`, `[user.2]` и строкового кодирования списков.

## Входные данные

- `app.conf` — пример, использующий все возможности формата;
- `broken.conf` — файл с ошибкой (незакрытые список и блок) для демонстрации сообщений об ошибках.

```
server {
    host = 0.0.0.0
    port = 8080
    timeouts {
        read  = 30
        write = 15.5
    }
}
tags = [web, "api, v2", 42, true]
user { name = Анна;  role = admin }
user { name = Борис; role = guest; groups = [dev, ops] }
```

## Запуск
### Через Docker

Файл `app.json` будет создан в текущей папке:

```bash
docker run --rm -it -v "$PWD":/app -w /app nim:2.2 bash -c \
  'nim c -d:release conf2json.nim && ./conf2json app.conf app.json'
```


Нужен компилятор Nim (nim-lang.org, или `sudo apt install nim`).

```bash
nim c -d:release conf2json.nim
./conf2json app.conf              # JSON в консоль
./conf2json app.conf app.json     # JSON в файл
./conf2json broken.conf           # пример сообщения об ошибке
```

Или без отдельной компиляции: `nim r conf2json.nim app.conf`.

## Пример вывода

```json
{
  "name": "Демо-сервис \"Заметки\"",
  "version": 1.4,
  "debug": true,
  "owner": null,
  "server": {
    "host": "0.0.0.0",
    "port": 8080,
    "tls": false,
    "timeouts": { "read": 30, "write": 15.5 }
  },
  "tags": ["web", "api, v2", 42, true],
  "user": [
    { "name": "Анна", "role": "admin" },
    { "name": "Борис", "role": "guest", "groups": ["dev", "ops"] }
  ]
}
```

(в реальном выводе каждый элемент на своей строке)

```
Ошибка в broken.conf: строка 5, позиция 1: незакрытый список '['
```
