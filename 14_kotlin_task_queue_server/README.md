# 14. Kotlin — сервер очереди задач

## Постановка задачи

Сервер хранит общую **очередь задач**. Одни клиенты («постановщики») кладут в неё задачи с приоритетом, другие («исполнители») забирают задачи, выполняют и сообщают о результате. Это упрощённая модель брокера задач, на которой строятся фоновые обработчики в реальных системах.

Требования:
- задачи выдаются по **приоритету** (1–10, больше — важнее), при равном приоритете — в порядке поступления (FIFO, «первым пришёл — первым ушёл»);
- исполнитель может ждать задачу, если очередь пуста (команда `WAIT`, до 30 с);
- задачу может завершить или вернуть в очередь только тот клиент, который её взял;
- если исполнитель отключился, не завершив задачу, она возвращается в очередь;
- несколько клиентов работают одновременно.

Реализация: сервер принимает подключения через `ServerSocket` и запускает **отдельный поток** на каждого клиента. Очередь — `PriorityBlockingQueue` из стандартной библиотеки Java: она **потокобезопасна** (корректно работает при одновременном доступе из многих потоков) и умеет блокирующе ждать появления элемента — на этом построена команда `WAIT`.

## Протокол

Текстовый, одна команда — одна строка. Последняя строка ответа начинается с `OK`, `ERR`, `TASK`, `EMPTY` или `BYE`; строки с отступом — содержимое списка.

| Команда | Ответ |
|---|---|
| `PUSH <1-10> <описание>` | `OK задача #N в очереди` |
| `TAKE` | `TASK <id> <приоритет> <описание>` или `EMPTY` |
| `WAIT` | как `TAKE`, но ждёт задачу до 30 секунд |
| `DONE <id>` / `FAIL <id>` | задача выполнена / вернуть в очередь |
| `LIST`, `STATUS` | содержимое очереди / счётчики задач |
| `HELP`, `QUIT` | справка / отключиться |

## Запуск
### Через Docker

Соберите JAR-файлы в папке проекта:

```bash
docker run --rm -it -v "$PWD":/app -w /app debian:bookworm-slim sh -lc \
  'apt-get update && apt-get install -y --no-install-recommends default-jdk-headless kotlin && kotlinc Server.kt -include-runtime -d server.jar && kotlinc Client.kt -include-runtime -d client.jar'
```

В отдельном терминале запустите сервер:

```bash
docker run --rm -it -p 7001:7000 -v "$PWD":/app -w /app eclipse-temurin:17-jre \
  java -jar server.jar 7000
```

Запустите клиента в другом терминале; на macOS `host.docker.internal` указывает на хост-компьютер:

```bash
docker run --rm -it -v "$PWD":/app -w /app eclipse-temurin:17-jre \
  java -jar client.jar host.docker.internal 7001 --worker
```


Нужны JDK 11+ и компилятор Kotlin (`kotlinc`, sdkman или `sudo apt install kotlin`).

```bash
kotlinc Server.kt -include-runtime -d server.jar
kotlinc Client.kt -include-runtime -d client.jar

java -jar server.jar 7000                          # сервер (порт по умолчанию 7000)
java -jar client.jar localhost 7000 --worker       # автоматический исполнитель (можно запустить несколько)
java -jar client.jar localhost 7000                # интерактивный клиент
```

Вместо клиента можно использовать `nc localhost 7000`.

## Пример

Интерактивный клиент:

```
> PUSH 3 обновить зависимости
OK задача #1 в очереди
> PUSH 9 починить прод
OK задача #2 в очереди
> PUSH 11 bad
ERR формат: PUSH <приоритет 1-10> <описание>
> LIST
  #2 [приоритет 9] починить прод
  #3 [приоритет 5] написать тесты
OK в очереди 2
```

Исполнитель:

```
Взял задачу #2 (приоритет 9): починить прод
OK задача #2 выполнена
Взял задачу #3 (приоритет 5): написать тесты
OK задача #3 выполнена
```

Лог сервера:

```
[18:26:30] 127.0.0.1:42034 взял задачу #2
[18:26:30] задача #2 возвращена в очередь (исполнитель 127.0.0.1:42034 отключился)
[18:26:31] 127.0.0.1:42032 взял задачу #2
```
